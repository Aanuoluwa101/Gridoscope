Gridoscope — IoT Energy Monitoring Pipeline
Gridoscope is a personal data engineering project that simulates a city-scale smart meter network and builds a complete data pipeline around it — from real-time event streaming through to analytical dashboards.
The system simulates 500 (or any other number set) smart meters across 5 city zones (residential, commercial, and industrial) generating energy consumption readings at tiered intervals — every 5 minutes for residential, 2 minutes for commercial, and 1 minute for industrial - these I think are tweakable too. Each meter is modelled as a state machine that can transition between normal operation, degraded performance, fault, and silent states, producing realistic electrical readings including voltage, current, power factor, and grid frequency alongside consumption data.
Events flow from a Python async producer into Apache Kafka (5 partitions, one per zone) where two consumer groups process them in parallel. The aggregation consumer group maintains stateful 5-minute tumbling windows per zone, computing demand totals, anomaly detection using per-hour exponential moving averages, and fleet health metrics, pushing results to a Power BI streaming dataset for a live operational dashboard. Simultaneously, a Kafka S3 Sink Connector durably writes every raw event to Amazon S3 partitioned by date and hour.
The batch pipeline picks up from S3 — Apache Airflow orchestrates hourly COPY INTO loads into Snowflake's raw layer, followed by daily dbt transformation runs that build staging models (typed, cleaned, enriched) and mart models (aggregated, business-ready) used by a Power BI historical analytics report covering demand heatmaps, customer segment breakdowns, zone consumption trends, and meter health scorecards.

The project deliberately covers both the streaming path (Kafka, Python asyncio, stateful consumers, Power BI streaming) and the batch path (S3, Airflow, Snowflake, dbt, Power BI Desktop) in one unified system — because real data engineering roles require fluency in both, and most learning resources cover them in isolation.
